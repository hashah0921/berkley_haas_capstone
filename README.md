# Capstone: Cryptocurrency Market Prediction

Claude-generated, based on the capstone proposal (Google Doc). Notebook structure/style loosely follows a prior
Berkeley Haas capstone (predictive maintenance) used as a style reference during development; that reference
project is not part of this repository.

## Business understanding
Crypto markets trade 24/7 with extreme volatility. Without a quantitative predictive tool, investors, fund
managers and corporate treasury teams are left reacting emotionally or on lagging indicators — often buying at
peaks and panic-selling at dips. A working directional-prediction model would let **asset managers, corporate
treasury officers, and fintech product managers** set dynamic stop-losses, time portfolio rebalancing better, and
improve risk-adjusted returns. (Full version in [2_crypto_market_prediction.ipynb](2_crypto_market_prediction.ipynb)'s
"Business understanding" section.)

## Research question
Can 15-minute price sequence data combined with engineered momentum indicators and market metrics predict
24-hour directional price movement and returns for major cryptocurrencies?

## Summary of findings

**Main notebook:** [2_crypto_market_prediction.ipynb](2_crypto_market_prediction.ipynb) · also see
[1_crypto_exploratory_data_analysis.ipynb](1_crypto_exploratory_data_analysis.ipynb) and
[3_news_sentiment_analysis.ipynb](3_news_sentiment_analysis.ipynb).

- **EDA on real data** (23 coins, 2013–2021): crypto returns are strongly fat-tailed (Bitcoin daily-return
  kurtosis ≈ 10 vs. 0 for a normal distribution) and major coins move together — BTC/ETH daily returns correlate
  at r = 0.52 (p ≈ 6×10⁻¹⁴⁷, a Pearson significance test) — this favors tree ensembles/RNNs over linear-Gaussian
  baselines and justifies a BTC-relative momentum feature. No meaningful day-of-week volume seasonality,
  consistent with 24/7 trading.
- **Main pipeline notebook, on its current data:** a `RandomizedSearchCV` + `TimeSeriesSplit` grid search tunes
  XGBoost (best CV ROC AUC 0.855, confirmed by an exhaustive `GridSearchCV` over the same optimum); the resulting
  ensemble (XGBoost + GRU) reaches **84.9% test accuracy / 0.905 AUC**, clearing the proposal's 55–60% target.
  Tellingly, a plain **cross-validated logistic regression matches or beats it (CV AUC 0.860)** — a strong sign
  the pattern being learned is simple. **None of these numbers are trustworthy as a market finding** — the
  notebook currently runs on a synthetic 15-minute placeholder (`data/coin_price_15min.csv`) with an injected
  predictable cycle, not the real Kaggle 15-minute file (see Data and Caveats below).
- **Honest real-data baseline:** the same feature set, lightly tuned, run on **real daily Bitcoin prices**
  (via `app.py` / `api.py`) gets **~53–56% test accuracy / ~0.52–0.56 AUC at a 1-day horizon** — barely above a
  coin flip. This is the more credible answer to the research question today, and the main pipeline's reported
  84.9% should be read as a pipeline check, not a finding, until it's re-run on real 15-minute data.
- **News sentiment:** a VADER-based scoring → daily-aggregation → export pipeline works end to end, but runs on
  a synthetic, labeled-placeholder headline generator (no real news source is configured) — treat any correlation
  it reports as a demonstration of the mechanism, not a market result.
- **Bottom line:** the modeling *approach* (feature engineering, chronological split with embargo, tuned
  ensemble, interpretability) is sound and the pipeline runs cleanly end to end, but the central research
  question is still unanswered — it depends on swapping the real Kaggle 15-minute file in for the placeholder.
- **For non-technical stakeholders:** see the main notebook's plain-language "Key findings & recommendations"
  section — short version: **do not use this for live trading decisions yet**; get real data first.

## Notebooks & app

### [1_crypto_exploratory_data_analysis.ipynb](1_crypto_exploratory_data_analysis.ipynb)
Question-driven EDA on the real daily coin data: coverage per coin, nulls/duplicates/missing-day checks, BTC vs
ETH price, fat-tailed return distribution, per-coin volatility, cross-coin return correlation, total market cap
over time, day-of-week volume check, plus a sanity pass on the synthetic 15-minute placeholder explaining why its
modeling results shouldn't be trusted yet. Mixes **matplotlib** (most charts), **seaborn** (correlation heatmap,
return-distribution boxplot) and an interactive **Plotly** candlestick chart.

### [2_crypto_market_prediction.ipynb](2_crypto_market_prediction.ipynb)
0. **Business understanding** — the real-world problem and who benefits from solving it
1. Config & data loading (real file if present, else synthetic 15-min fallback)
2. Feature engineering — multi-horizon returns, RSI, MACD, EMA gaps, rolling volatility, range, volume spike, hour-of-day
3. Chronological 70/15/15 split with a 96-bar embargo (avoids leakage from the overlapping 24h target)
4. **Evaluation metrics** — what accuracy, ROC AUC and MAE each measure, and why all three (ties back to the proposal's own stated success criteria)
5. Baselines — random walk, naive momentum, logistic + ridge, including a **cross-validated** logistic AUC for fair comparison with the tuned models below
6. **Hyperparameter grid search** — `RandomizedSearchCV` over `TimeSeriesSplit` folds tunes XGBoost's depth, learning rate, subsampling and regularization (no shuffling, so every fold validates on the future), plus an exhaustive `GridSearchCV` over the two most sensitive hyperparameters as a cross-check
7. XGBoost (tuned classifier + regressor)
8. GRU over 32-bar sequence windows (needs PyTorch; on macOS set `torch.set_num_threads(1)` — see Caveats), with a train/validation loss curve
9. Ensemble (averaged), plus a **binomial significance test** of accuracy vs. 50% chance
10. Interpretability — permutation importance & SHAP, with a written interpretation of which features drive predictions and why
11. Conclusions (technical — with real numbers from this run, and why they don't yet answer the research question)
12. **Key findings & recommendations** — plain-language summary and prioritized next steps for non-technical stakeholders

Target: binary 24h direction (`y_dir`) and 24h forward return (`fwd_ret`), 96 bars ahead. Success criteria from
the proposal: directional accuracy above 55–60% and lower MAE than the baselines.

### [3_news_sentiment_analysis.ipynb](3_news_sentiment_analysis.ipynb)
Scores headlines with VADER (lexicon-based, no network/API call needed), aggregates to one sentiment score per
day, plots it against same-day BTC return, and writes `data/news_sentiment_daily.csv` for the other notebook/app
to consume. Uses a labeled synthetic headline generator when no real headline file is supplied — see the
notebook's own caveats before citing any correlation it reports.

### [app.py](app.py) (Streamlit)
Interactive demo over the **real daily coin data**: pick a coin and a prediction horizon, see its price chart,
sentiment overlay (if `data/news_sentiment_daily.csv` exists), and a live-retrained, lightly-tuned XGBoost
model's test accuracy/AUC and feature importances. On Bitcoin this currently reports **~53–56% test accuracy /
~0.53 AUC at a 1-day horizon** — a useful real-data contrast with the inflated ~85% seen on the synthetic
15-minute pipeline (see Caveats).

### [api.py](api.py) (FastAPI)
The same model as `app.py`, served as JSON instead of a UI — both import [crypto_lib.py](crypto_lib.py), so they
can never disagree. Trained models are cached in-memory per `(coin, horizon_days, use_sentiment, n_search_iter)`
combo, so repeat calls are near-instant after the first.

| Endpoint | Purpose |
|---|---|
| `GET /docs` | Interactive Swagger UI |
| `GET /health` | Liveness check |
| `GET /coins` | List all 23 coins with row count, date range, last close |
| `GET /coins/{coin}/price?limit=100` | Recent daily OHLCV rows for one coin |
| `GET /predict/{coin}?horizon_days=1&use_sentiment=false&n_search_iter=15` | Train/reuse-cached model, return accuracy, AUC, today's P(price up), best hyperparameters, top features |
| `GET /sentiment/latest` | Most recent daily sentiment score (404 if notebook 3 hasn't been run) |

```bash
uvicorn api:app --reload --port 8000
curl http://127.0.0.1:8000/coins
curl "http://127.0.0.1:8000/predict/Bitcoin?horizon_days=1"
```
Coin names in the URL are case-insensitive (`/predict/bitcoin` works). Same disclaimer as the Streamlit app
applies — see the `disclaimer` field in every `/predict` response.

## Caveats
- **The 15-minute series is still synthetic.** The ~85% test accuracy in `2_crypto_market_prediction.ipynb` comes
  from a weak injected cycle in that placeholder and should not be reported as a real finding — the Streamlit
  app's ~53–56% on real daily Bitcoin data is a more honest baseline for what this approach actually achieves.
- **On macOS, xgboost and torch bundle separate OpenMP runtimes** that can crash (segfault) a GRU forward pass
  if both are imported in one process. Fixed in this repo with `torch.set_num_threads(1)` right after importing
  torch; needed if you add more PyTorch code elsewhere.
- **News sentiment is a synthetic placeholder** with a deliberately injected correlation to BTC returns, purely
  to demonstrate the scoring/merge/export pipeline. Swap in real headlines before drawing any conclusion from it.
- Transaction costs, slippage and regime changes are not modeled anywhere; accuracy above 50% does not by itself
  imply a profitable strategy.
